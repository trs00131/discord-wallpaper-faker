# Discord Wallpaper Faker

Discord で画面全体を共有した時だけ、壁紙を自動で無難な物に切り替える Windows 用の常駐アプリです。
アニメ壁紙を見られたくない人向け。共有が終われば元の壁紙に自動で戻ります。

制作者: TRS00131 (https://github.com/trs00131)

## 特徴
- 検知は Discord のログを読むだけ。Discord 本体は一切変更しない (クライアント改造ではない)
- 全画面共有だけに反応する。ウィンドウ共有・タブ共有では切り替わらない
- 通知領域 (トレイ) に常駐し、待機中 / 監視中 / 共有中 がアイコンで分かる
- スタートアップ登録すると、ログイン時は待機状態で潜み、Discord が起動したら監視を始める
- インストールはポータブル方式。展開したフォルダの中で全部動く

## 使い方
1. Releases から discord-wallpaper-faker-installer.exe をダウンロードして実行
2. 設定ボタンから、フェイク壁紙と元の壁紙のパスを設定する
3. 設定で「スタートアップに登録する」を ON にする

ダウンロードした exe の初回起動時に「Windows によって PC が保護されました」と出たら、「詳細情報 → 実行」を押してください (署名のない exe では必ず出ます)。

## ソースから作る場合
Python を入れた状態で build.bat を実行すると、dist に installer ができます。

## v7 の変更
- トレイに入らず右上の点になっていた問題: トレイ用の Windows 関数の戻り値の型 (64bit ハンドル) を全部明示した。直らなかった場合に備えて、原因がログに残るようにもした
- 「管理者として再起動」ボタンを追加。今の権限 (管理者 / 通常) もメイン画面に表示される

## 最終仕上げ (ポータブル化)
- インストール後は、ZIP を展開したフォルダの中で全部動く。本体 exe はインストーラーと同じフォルダに展開され、設定とログは同じフォルダの data の中に入る。LOCALAPPDATA には何も置かない (旧版の置き場が残っていれば、インストール時に片付ける)
- フォルダごと引っ越す場合は、引っ越し先でインストーラーを実行し直すこと (自動起動の向き先が新しい場所に直る)

## v6 の変更 (改名・トレイ常駐・自動起動の追加・パスのみ登録)

## v5 の変更 (実ログで確定＋画面と配布の作り直し)
送ってもらった診断ログ (FakeWallpaper_logs.zip) を解析して直した。

- 元に戻らない問題: 共有開始は 21:30:11 に正しく検知できていた。本物の終了の行は renderer_js.log の「(stream) 側の接続終了」系だったが、v4 の終了フレーズに無く、拾えた唯一の終了候補はアプリ音声 (loopback) の停止行で、それは点滅防止に弾かれていた。さらに音声通話の行が「共有中」の合図として扱われ続け、通話中は永遠に戻らない状態だった。v5 の判定は実物の行に合わせた: 開始は source id の screen-handle / window-handle、終了は (stream) 側の接続終了と activeStream: false だけを見る。loopback の行は終了に使わない
- build.bat の成果物は dist の fake-wallpaperinstaller.exe だけにした (本体は作業フォルダで作って埋め込み、後片付けする)
- インストーラーはデスクトップにショートカットを作らない。自動起動の登録もインストーラーではしない
- 画面を作り直した。メイン画面は状態とボタンだけ、設定ボタンで設定パネルが開く。管理者権限で常駐させるか (ログイン時自動起動) は設定パネルで決める。変更すると保存時に Windows の管理者確認 (UAC) が出る
- 完全終了ボタンを追加した。押すと壁紙を元に戻してから完全に終了する (右上の点を右クリックでも完全終了)

## v4 の変更
- 元の壁紙のパスも設定できるようにした。設定画面に「元の壁紙」の欄を追加（画像を選ぶ／パスの貼り付け／今の壁紙を登録）。手動で指定した場合は、自動で記録した物より優先してその画像に戻す。空にすると自動記録に戻る
- 検知に WebRTC の画面取り込みの語彙 (ScreenCapturer / WindowCapturer など) を追加した
- 「診断ログをデスクトップにZIPで出す」ボタンを追加。自分のログ2つに加えて、Discord 自身のログファイルの末尾も入る。共有テストの後にこれを押して、そのZIPを妖精に送れば、推測ではなく実物の行で判定を確定できる

## v3 の修正 (点滅と転送量検知の廃止)
実機で「共有後に元の壁紙とフェイク壁紙がゆっくり点滅する」問題と、「転送量で測る方式は画像アップロードでも反応してしまう」という指摘を受けて修正。

- 点滅の原因: v2 の終了判定が destroy / release / closed のような汎用の単語でも反応していて、共有中のログに普通に出てくる単語で壁紙が戻り、また入り、を繰り返していた。終了判定は stream stopped のような強い言い方だけに限定した
- さらに点滅防止として、切り替えた直後10秒は終了扱いにしない、共有中のログがまだ流れている間は戻さない、という保持ルールを追加。終了の合図を取りこぼした場合は、共有のログが45秒途絶えた時点で戻す
- 転送量 (data量) で測る補助検知は廃止した。壁紙を切り替える判定は、Discord内部のログ (WebRTC/メディアの記録) だけに一本化
- 代わりに Discord のウィンドウ状態の変化を記録専用で監視するようにした (共有開始時に出るウィンドウ変化があれば次の判定材料になる。壁紙は切り替えない)

## v2 の修正 (v1 で検知できなかった原因と対策)
実機で全画面共有を検知できなかった原因は、妖精側の作りの甘さだった。3つ直した。

1. Discord のログフォルダには discord-webrtc_0 のように拡張子のないファイルがあり、映像まわりはそこに出るのに、v1 は .log ファイルしか見ていなかった → フォルダ内の全ファイルを見るように変更
2. 64bit Windows のハンドル受け取り方が間違っていて、フォルダ監視とプロセス確認が壊れていた可能性が高い → 受け取り方を明示して修正。失敗したら理由がログに残るようにした
3. 監視中に新しく作られたログファイルを丸ごと読み飛ばしていた → 先頭から読むように変更


## 配布について
v2 からは fake-wallpaperinstaller.exe だけで配れる。本体はインストーラーの中に埋め込んである。

## なぜ合法寄りなのか
- Discord本体のファイル・通信・メモリは一切いじらない（クライアント改造ではない）
- 読むのは、Discordが自分のPCに書いているログファイルと、Discordのウィンドウ状態だけ
- 変えるのは、Windowsの壁紙だけ（Windows公式の方法で変更）
- 外部サーバーなし。全部ローカルで完結

## 使い方
1. このフォルダで build.bat を押す（Pythonが必要）。dist フォルダに exe ができる
2. dist の fake-wallpaperinstaller.exe を実行する（管理者の確認が出る）。配る時はこの1ファイルでいい
3. インストールを押す。本体が起動するので、設定ボタンから設定パネルを開き、フェイク壁紙の画像を選ぶ
4. ログイン時に自動で待機させたい場合は、設定パネルの「管理者権限で常駐させる」をONにする (保存時に管理者確認が出る)
5. アンインストールはインストーラーのアンインストールボタン

## 実機テスト手順（v2 の確認）
1. 設定画面でフェイク壁紙を選ぶ
2. 「3秒だけテスト切替」を押す → フェイク壁紙になって、3秒で元に戻ればOK
3. Discordで通話に入り、ディスプレイ全体の共有をする → フェイク壁紙に変わるか確認
4. 共有を止める → 元の壁紙に戻るか確認
5. ウィンドウ（タブ）だけの共有をする → 変わらないのが目標
6. 結果がどうあれ、設定画面の「ログフォルダを開く」から discord_log_hits.txt と fake_wallpaper.log を妖精に送る。WebRTCログの生の行とウィンドウの変化が残っているので、次は判定をピンポイントで合わせられる

## 正直な注意点
- Discord のログに共有開始がどう書かれるかは、実機の discord_log_hits.txt で最終確認する。v2 は WebRTC ログの生の行も残すので、書かれていれば必ず材料が残る
- 共有の最初の瞬間に間に合うかは、Discord がログを書くタイミング次第
- Wallpaper Engine など壁紙を管理する別アプリと併用した場合の動作は未確認
